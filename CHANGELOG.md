## v3.1.0 - 2026-08-14

- _security_: Scope a caller-supplied `TLSClientConfig` to a per-`Server` HTTP client instead of mutating the process-global `http.DefaultTransport` (CWE-295, improper certificate validation via shared state).
The standard transport and TLS configuration are cloned, preserving every transport option without sharing mutable TLS state. `Configuration.HTTPClient` can explicitly inject proxying, tracing, or policy behavior. If a TLS configuration cannot be applied to a non-standard transport, `New` fails rather than bypassing either policy.
- _new-product-feature_: Bound requests to 60 seconds by default. `Configuration.Timeout` selects a different bound, while `DisableTimeout` explicitly restores an unbounded client for callers that enforce context deadlines. This intentionally changes the zero-value behavior from no timeout to a production-safe timeout.
- _security_: Stop caching the OAuth bearer access token in the process environment; cache it in process memory instead (CWE-526, cleartext storage of a credential in an environment variable).
The token was previously written with `os.Setenv` under an `SS_AT_*` key, which exposed it to any reader of the process environment and to every child process. Those variables are no longer written or read at all.
In-process token reuse and the per-URL/per-username collision keying are preserved; the only removed behavior is cross-process token inheritance via the environment.
- _bug-fix_: Guard against a nil `*http.Response` in `accessResource` so a transport error (including a `Timeout`-induced context deadline) returns an error instead of panicking on `statusCode.StatusCode`.
- _bug-fix_: Report why a health check failed instead of returning a bare `invalid URL`. `checkJSONResponse` now returns the transport or read error alongside its verdict, and `checkPlatformDetails` wraps both probe errors with the URLs it probed, so an untrusted CA, blocked egress, DNS failure, unhealthy or proxied endpoint, and a genuinely wrong `ServerURL` are no longer indistinguishable to the caller. The cause previously reached only the logger, so anything reporting on the SDK's behalf (for example an operator writing to a resource status) saw only `invalid URL`. The underlying error is wrapped, so `errors.Is`/`errors.As` work (for example against `x509.UnknownAuthorityError`). Both functions are unexported: no public API change.
- _security_: URL-encode search parameters in `urlForSearch` via `url.Values` so caller-supplied search terms and field names cannot inject or override query parameters (CWE-88/CWE-74; dive-security.md Finding 1.2).
- _security_: `url.PathEscape` server-provided field `Slug` values before interpolating them into request paths (defense-in-depth against malicious server responses; dive-security.md Roadmap #9).
- _security_: Include the credential `Domain` in the token cache key. Two `Server` instances sharing a `ServerURL` and username but differing only by `Domain` (for example a local account and a directory account) previously hashed to the same cache key, so one could be served a bearer token obtained with the other's credentials.
- _bug-fix_: Close HTTP response bodies in `handleResponse`. Every API call read the response body but never closed it, leaking the underlying connection/file descriptor on each request in long-running consumers.
- _security_: Bound HTTP response reads so a compromised or misdirected endpoint cannot exhaust process memory with an arbitrarily large body (memory-exhaustion DoS). General API and attachment responses are capped at 100 MiB, vault metadata at 10 MiB, and health and authentication responses at 1 MiB; an oversized response returns an error rather than a truncated payload.
- _security_: Stop logging raw response bodies on JSON parse errors (dive-security.md Roadmap #8). The unparsed body of a secrets API response can contain the secret material itself; the log line now carries the parse error and the body length instead.
- _bug-fix_: Harden `GeneratePassword`: decode the response as the JSON string the endpoint returns instead of blindly stripping the first and last byte, which panicked on a response shorter than two bytes and mishandled escaped characters; and return an error for a slug that does not identify a template field instead of proceeding with field ID `0`.
- _bug-fix_: Fix the inverted token-cache expiry formula so a cached token is served for 90% of its lifetime instead of 10%. Tokens were re-fetched after a tenth of their lifetime, sending the credentials on ~10x more grant requests than necessary; a token revoked server-side is still evicted immediately by the existing 401/403 cache clear.
- _new-product-feature_: Add an optional `Configuration.MaxResponseBytes` (`int64`) that overrides the default 100 MiB cap on API response bodies, for on-premises Secret Servers configured to allow file attachments larger than the default cap. A zero value keeps the default.
- _bug-fix_: Evict a rejected access token when talking to a Platform. The cached token is first used on the vault-broker request inside Platform discovery, which returned before the existing 401/403 eviction could run, and the eviction itself keyed on `ServerURL` after discovery had rewritten it to the vault address. A token the Platform refused was therefore kept and replayed on every subsequent call, leaving the client failing for the rest of the token's lifetime with no recovery short of restarting the process. Found by running the battery against a live Platform; Secret Server was unaffected.
- _security_: Include a process-random HMAC-SHA-256 discriminator for the credential password in the token cache key. A cache hit returns before the grant request is built, so keying only by URL, domain, and username allowed a stale, rotated, or mistyped password to reuse a token obtained with another password. The randomized HMAC distinguishes passwords without retaining plaintext or exposing a reusable offline password verifier in a cache-key memory disclosure.
- _bug-fix_: Evict the cached token on a 401/403 from search and file-upload requests, matching the other API calls. A token the server had rejected during a search or upload was previously replayed until a regular API call happened to evict it.
- _security_: Redact the secret fields of `UserCredential` when it is formatted or encoded with `encoding/json`. `Server` embeds `Configuration` and its fields are exported, so diagnostic formatting or generic JSON telemetry previously exposed the configured password and supplied token. JSON configuration files still decode normally; marshaled credentials are deliberately diagnostic and do not round-trip their secret fields. Other reflection-based serializers can still inspect exported fields and must not receive a live configuration.
- _security_: Validate Platform-discovered vault URLs before sending a Platform bearer token. Discovered vaults must use HTTPS and must be same-origin, a Delinea Secret Server Cloud domain, explicitly listed in `AllowedVaultHosts`, or accepted by `VaultURLValidator`. User information, query strings, and fragments are always rejected. Cross-origin on-premises deployments must add their expected vault host.
- _security_: Restrict general redirects to the original origin and disable redirects for password and client-credential token grants, preventing Go's 307/308 behavior from replaying credentials to a redirect target.
- _security_: Validate OAuth grants before caching or using them: `access_token` must be non-empty, `expires_in` must be positive, and any supplied `token_type` must be Bearer. Platform detection now carries an explicit server kind, so an empty Platform token cannot fall through into a Secret Server password grant against the discovered vault.
- _bug-fix_: Coalesce concurrent token-cache misses per credential while allowing different credentials to authenticate concurrently. Cached tokens carry generations, so a delayed 401 for an old token cannot evict a newer refresh. A 401 for a caller-supplied token never evicts the password-grant cache. The cache is bounded to 1,024 entries.
- _bug-fix_: Require a successful HTTP status and strict JSON or the exact legacy `Healthy` value from health probes. HTTP 500 bodies containing that word are no longer accepted. Non-2xx responses now return an exported `*HTTPError` with a status code and a bounded, control-character-sanitized diagnostic while preserving the historical error-string shape.
- _new-product-feature_: Add context-aware variants of every network operation (`SecretContext`, `SecretsContext`, `SecretByPathContext`, create/update/delete, templates, and password generation). Context cancellation covers health discovery, token-flight waits, retry backoff, API requests, and attachment transfers.
- _new-product-feature_: Retry only safe GET/HEAD requests after transient network errors, HTTP 429, and HTTP 5xx. The default is two retries with bounded exponential jitter and `Retry-After` support. Mutating calls, deletion, upload, token grants, and password generation are never retried. `MaxRetries`, `RetryBaseDelay`, and `DisableRetries` control the policy.
- _breaking-change_: Raise the module language version to Go 1.26, the oldest release still supported upstream, and test all packages with the race detector on the 1.26.0 and 1.26.5 patch lines. Add vet, Staticcheck, and reachable-vulnerability analysis, update checkout/setup actions to pinned v7 release commits, and move the release workflow off Go 1.13.
This is a build requirement, not an API break: no exported symbol changes and the module path stays `/v3`. A consumer whose own `go` directive is below 1.26 must raise it before building this release, because automatic toolchain switching is driven by the main module's directive and not by a dependency's requirement. Every known third-party importer already declares go 1.26 or newer; Delinea's own GitHub Action and GitLab CI integrations still declare go 1.21, and adopting this release there is a one-line bump — `go mod tidy` raises the directive automatically, verified against both integrations. The previous floor of go 1.14 dated to February 2020 and existed only because the test suite uses `testing.T.Cleanup`; keeping it would have let this SDK be built with a toolchain that no longer receives standard-library security fixes.
- _tests_: Run the live Secret Server and Platform battery once, with independent `TSS_REQUIRE_SECRET_SERVER` and `TSS_REQUIRE_PLATFORM` gates. Required targets now fail on missing or unsuitable fixtures instead of skipping, and secret paths support both slash and backslash separators.
